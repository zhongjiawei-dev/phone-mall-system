# V1.5 升级说明

## 升级原则

在原有 Flask + Jinja2 工程上做增量升级，保留页面路由、主要元素 ID 和 Selenium 页面对象，不重写为全新项目。V1 的页面与交互继续可用，新增能力通过数据库、业务层和后台页面逐层补齐。

## 已修复的 V1 业务漏洞

| 编号 | 问题 | 风险 | V1.5 处理 |
| --- | --- | --- | --- |
| B1 | 购物车不校验库存 | 可加购超过库存，结算时才暴露 | 加购、改数量、结算三层校验 |
| B2 | 支付时才扣库存 | 两个待支付订单可能同时买到最后一件 | 下单事务内锁定库存，取消/退款释放 |
| B3 | 邮箱大小写敏感 | `Student@Example.com` 登不进 | 邮箱统一 `casefold` 存储与查询 |
| B4 | 订单状态只有待支付/已支付 | 无法发货、完成、取消、退款 | 七状态订单状态机 + 状态流水 |
| B5 | 数据在内存 | 重启丢失订单和库存 | SQLite 持久化 + 自动建表/种子 |
| B6 | 明文密码 | 数据库泄露即泄露密码 | PBKDF2-SHA256 哈希 |
| B7 | 无 CSRF | 第三方页面可伪造 POST | 全部写操作校验 Session Token |
| B8 | 无后台 | 运营无法发货/退款/调库存 | `/admin` 管理后台 |

## 新增能力

- `shop/schema.sql`：9 张表，含外键与索引；
- `shop/db.py`：连接管理、建表、种子数据、演示重置；
- `shop/services.py`：计价、库存、状态机、优惠券、统计；
- 管理后台：数据看板、订单管理、库存管理、优惠券、账号；
- 优惠券：`WELCOME10`、`SAVE5`、`VIP20`，支持固定/百分比、门槛、封顶、次数、有效期；
- 售后：取消、退款申请、管理员退款、确认收货；
- 测试：原有 UI 用例 + 新增业务规则用例。

## 数据库升级

V1 没有数据库。V1.5 首次启动自动创建 `shop/data/shop.db` 并执行 `schema.sql`，写入演示数据。需要恢复初始状态时访问本机 `/dev/reset`，或停止服务后删除数据库文件再启动。

## 状态机

```text
pending → paid → shipped → completed
   │        │        │
   │        └────────┴──→ refunding → refunded
   └──→ cancelled
```

允许的状态迁移集中在 `shop/services.py` 的 `ACTION_RULES`，路由只调用业务层，不直接改状态。

## 兼容性

- 原有路由 `/`、`/login`、`/cart`、`/checkout`、`/order/<no>`、`/pay/<no>` 保留；
- 原有页面元素 ID（`search-input`、`add-cart`、`cart-total`、`submit-order`、`order-status`、`pay-confirm` 等）保留；
- 原有演示账号和商品价格保留；
- 原有 Selenium 页面对象无需重写，补充业务测试即可。
